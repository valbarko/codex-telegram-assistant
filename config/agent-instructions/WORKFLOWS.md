## Completion

For multi-step work, infer a verifiable finish line from the requested outcome and
the project's workflow. Continue through authorized implementation, checks, and
closeout; a progress update is not a stopping point. Reuse authorization already
given. Stop when user input is essential, an explicit limit is reached, or an
external blocker leaves no useful independent step.

For work at risk of context compaction, keep a brief checkpoint of decisions,
completed/remaining steps, checks, and blockers in the existing journal or outside
tracked source. Narrow follow-ups preserve settled decisions unless new evidence
or Valentin's correction changes the result.

## Release

- “сделай пр” alone: commit, push, and create a draft PR.
- “закрой”, “сделай пр и закрой”, or “заверши задачу”: make the PR ready, wait for
  CI, merge, deploy to production when supported by the project flow, verify
  production smoke and release metadata, then remove task branches and worktree.
- Explicit limits such as “без деплоя” narrow that scope. A status question such as
  “закрыто?” supplies no new production authorization.

Preserve project checks, risk-specific safeguards, and owner-kept work. Reuse the
same authorization for a dictated follow-up; clarify only material ambiguity.

## Artifacts

Deliver the finished usable file when feasible. For substantial plans or artifacts,
check dates, names, numbers, totals, and labels against the source. Inspect an
available original chart, screenshot, or diagram instead of relying on retyped
details. Report what was verified and any source limitation.
