# Personal Memory v2

## Цель

Ассистент собирает личный контекст Валентина из разрешённых источников, хранит
исходные данные локально, отличает факты от выводов и использует память для
развёрнутых ответов и практических предложений.

## Минимальная архитектура

```text
Telegram / голос / будущие импорты
                 |
                 v
       SQLite + Markdown events
       канонический источник истины
          |             |
          v             v
     ABOUT / NOW     производные индексы
     подтверждённое  Hindsight + MemSearch
          \             /
           v           v
            один ответ Codex
```

### Канонический слой

- SQLite хранит реестр событий, задачи, статусы и напоминания.
- Markdown хранит читаемую копию каждого события.
- Удаление и исправление начинаются в каноническом слое.
- Hindsight и MemSearch можно полностью пересобрать из канонических данных.

### Компактный постоянный контекст

- `ABOUT.md` содержит только явно подтверждённые пользователем сведения.
- `NOW.md` строится из активных задач и напоминаний.
- Файлы находятся в `ASSISTANT_DATA_DIR/personal-context/<owner>/`.
- Автоматические наблюдения Hindsight не смешиваются с подтверждённым профилем.

### Hindsight

- `retain`: пакетное извлечение фактов из пользовательских сообщений, собственных
  голосовых и содержательных действий.
- Ответы ассистента остаются в исходном архиве, но не становятся фактами о
  пользователе.
- `recall`: локальный semantic + BM25 + graph + temporal retrieval для обычных
  запросов.
- `reflect`: только для явного глубокого анализа; не вызывается на каждом ходе.
- Luna используется для массового извлечения, Terra — для консолидации и редкого
  reflect. Финальное рассуждение выполняет текущий Codex.

### MemSearch

- поиск по исходным эпизодам и точным формулировкам;
- отдельный авторский корпус для личного и экспертного стиля;
- fallback при недоступности Hindsight.

### Операционное состояние

Задачи, сроки, напоминания и их статусы остаются в SQLite. Память может объяснять
контекст задачи, но не определяет, активна она или завершена.

## Доверие и provenance

Приоритет сведений:

1. явное `/remember` или исправление пользователя;
2. прямое сообщение пользователя;
3. подтверждённое действие или результат;
4. повторяющееся наблюдение Hindsight;
5. гипотеза ассистента.

Ответ должен разделять подтверждённые факты, вероятные выводы и предложения.
Каждый производный результат по возможности сохраняет `memory_id`, источник и
время исходного события.

## Источники

### Сейчас

- текстовые сообщения Telegram;
- собственные голосовые и их расшифровки;
- явные записи `/remember`;
- задачи, напоминания и подтверждённые действия;
- существующий локальный авторский корпус.

Пересланные чужие голосовые и пользователи режима «только расшифровка» в личную
память не попадают.

### Затем

1. Apple Notes: локальный импорт с устойчивыми source IDs, hash и временем
   изменения. Заблокированные заметки импортируются только после разблокировки
   владельцем в приложении Notes.
2. История ChatGPT: импорт официального экспорта как разговоров с отдельными
   ролями; утверждения ассистента не считаются фактами о пользователе.
3. Telegram history: импорт пользовательского экспорта или разрешённых чатов,
   а не чтение всех личных чатов через Bot API.

Все импортеры записывают данные сначала в единый журнал событий и только затем
обновляют производные индексы.

## Контроль качества

Перед расширением источников:

- загрузить текущий архив в Hindsight;
- проверить 20–30 реальных русскоязычных вопросов;
- измерить точность фактов, актуальность во времени, ложные утверждения,
  provenance, задержку и расход кредитов;
- сравнить MemSearch, Hindsight recall и редкий reflect;
- добавлять Sol или Graphiti только при измеримом выигрыше.
