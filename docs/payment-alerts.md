# Уведомления об оплатах проектов

Сервер `gmk-prod-1` проверяет оплаты по Москве каждый час с 09:00 до 20:00
включительно. В 21:00 и ночью проверок нет. Оплаты после последней дневной
проверки попадают в сводку в 09:00. Дневные оплаты тоже объединяются в сводку
на ближайшей проверке. Очень длинная сводка делится на несколько сообщений.
Если оплат нет, сообщение не отправляется.
Если сервер пропустил запуск, следующий плановый запуск дочитает накопившееся.

В сводку входят счета четырёх продуктов: «Тренер в кармане», «Где мои клиенты»,
«Где мои ученики» и «Тело в порядке». Указаны проект, клиент, сумма и назначение
платежа. Для ТВК, ГМК и «Тела в порядке» имя клиента ведёт в его закрытую
карточку. У ГМУ карточки клиента для владельца нет, поэтому имя остаётся текстом.
Платежи, которые тренеры и репетиторы заносят внутри своих CRM, не являются
оплатой продукта и сюда не входят.

`payment-alerts.timer` запускает `payment-alerts.service` на сервере. PHP-скрипт
`scripts/server-payment-alerts.php` читает четыре базы через
`scripts/payment-snapshot.php` и отправляет сообщения владельцу через Telegram
Bot API. Компьютер владельца для этого не нужен. Локальная проверка в основном
процессе помощника удалена, чтобы не было дублей. Токен бота и ID владельца
хранятся только в `/etc/codex-payment-alerts.json` с правами `0600`; файл не
попадает в репозиторий. Формат: `telegram_bot_token` и `owner_chat_id`.

Курсоры и номера уже отправленных счетов хранятся в
`/var/lib/codex-payment-alerts/payment-alerts.sqlite`. Имена и суммы в этом файле
не сохраняются. Перед первым включением расписания нужно перенести состояние
локального монитора или выполнить `php server-payment-alerts.php --init`, чтобы
не отправить всю историю. `--check` проверяет доступ ко всем четырём базам без
отправки. На каждом плановом запуске сначала успешно читаются все четыре базы,
затем отправляется сводка. При ошибке отправки платежи остаются для следующего
запуска. Telegram не предоставляет ключ идемпотентности для `sendMessage`, поэтому
сбой строго между успешной отправкой и записью в SQLite может дать повтор.

Код живёт в `/opt/codex-payment-alerts/current`; версии можно менять атомарно
через симлинк. Systemd-файлы находятся в `infra/payment-alerts.service` и
`infra/payment-alerts.timer`. Проверка расписания:

```bash
systemd-analyze calendar '*-*-* 09..20:00:00 Europe/Moscow'
systemctl list-timers payment-alerts.timer
```
